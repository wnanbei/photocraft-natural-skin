# Natural Skin 原生伴随程序可行性

> 本文是最初可行性阶段的记录。其后的原生交换和桌面实现见 [开发进展](native-development-2026-11-08.zh-CN.md)。

结论：**在不修改 PhotoCraft 的条件下可行，值得继续开发。** 已实现可运行的 Rust 后端，并与实际桌面程序完成独立实例联调；当前成果是可行性原型，尚未交付 GUI。开发目标已切为原生伴随程序，不再保留 WASM 产品线。

本轮使用 macOS arm64、Rust 1.98.1、未修改的 PhotoCraft **0.21.0（efb7ebd0c，2026-11-06）**。测试只使用生成的图片、独立配置与临时文档，没有连接用户日常编辑实例。原始测量和验证摘要见 [JSON](native-feasibility-2026-11-08.json)，复现见 [测试方法](testing.md)。

## 已实现和验证的部分

| 部分 | 结果 |
| --- | --- |
| 原生磨皮内核 | 复用已验证的 guided filter、Alpha 加权、分离皮肤区域和肤色调整，移除 WASM ABI |
| 预览基础缓存 | 源图由会话持有且不修改；半径/边缘保护改变时重建，强度/纹理/肤色范围/调色复用基础数据 |
| 阶段与耗时 | CLI 输出 Read、Analyze、Filter、Write、Complete 等事件；文件写完才报告整体完成 |
| 取消 | 内核支持检查点取消，预览混合按 32 行检查；取消的工作结果由调用方丢弃 |
| 文件交换 | RGB/RGBA TIFF，8/16 位整数或 32 位浮点，非预乘 Alpha，ICC 字节、DPI 保留；不覆盖已有输出 |
| 桌面连接 | Rust 客户端已通过私有 token 连接 loopback 控制接口；源版本检查可拒绝已过期结果 |
| 数据保真 | 实际桌面完成 8/16/32 位 × 原样/磨皮，共 6 次往返 |
| 原始快照 | 临时 `.pcraft` 中的原始浮点图块可取得，包括完全透明像素下的 RGB；目前仅研究脚本读回 |

本地格式检查、严格 Clippy 和 **25 个单元测试**通过。覆盖缓存失效、肤色范围扩大、源图不变、取消、区域上下文、Alpha/HDR/无效样本、TIFF 和源版本守卫。远端 CI、Windows/Linux 桌面和真实人像验收尚未运行。

## 预览性能为何能改善

伴随程序持有源图和中间数据，不必每调一次参数都让宿主重新执行完整滤镜。先为整个预览计算基础数据，再按当前皮肤范围、强度、纹理与调色混合。基础数据覆盖整个预览，扩大皮肤范围时不会漏掉上一次蒙版外的区域。新源图、文档版本、裁切或预览比例必须创建新会话；半径和边缘保护改变时重建缓存。

2026-11-08 在本机顺序运行、无同时构建或桌面测试，得到：

| 场景 | 首次计算 | 缓存后混合中位数 | 基础缓存 |
| --- | ---: | ---: | ---: |
| 512 × 384 预览 | 11.03 ms | 4.08 ms | 4.5 MiB |
| 1024 × 768 预览 | 48.70 ms | 16.40 ms | 18 MiB |
| 1024 × 768 完整内核 | 36.94 ms 中位数 | — | 21 MiB 工作区 |
| 6000 × 4000 完整内核 | 1309.46 ms 中位数 | — | 约 641 MiB 工作区 |

预览首次时间只测一次，混合测五次；完整内核测三次。24 MP 三次为 1300.91、1309.46、1615.27 ms。样本为程序生成的有噪声肤色图、变化 Alpha 和一个 HDR 样本，不代表所有人像。

计时包含内核工作区分配；预览包含源图复制及混合。**不包含 PhotoCraft 捕获/回传、TIFF 读写、缩放与显示上传**，不能据此承诺整条链路同样快，也不能与历史 WASM 宿主计时直接换算加速倍数。工作区之外还需源图、结果和文件解码内存，24 MP 峰值内存仍需优化。当前限制完整图 36 MP、预览 2 MP。

## 不修改主程序的实际交换路线

实际桌面接口和 headless 接口不同：`doc.render` 在桌面返回未知方法；`file.saveACopy`、`file.export.layersToFiles`、`file.placeEmbedded` 因环境文件路径权限被拒绝，不能据 CLI 能用就认定桌面可用。

已跑通的路线是：检查源文档 → 将指定像素图层复制到临时新文档 → 用受交换目录约束的 `app.save` 导出 → 原生处理 → `app.open` 打开结果。研究测试还验证了复制结果图层回原文档，再隐藏原层。后者需 **两次 Undo** 恢复图层；包含 Alpha 时不能直接让原层继续显示在下面，否则会重复合成。

所有捕获测试中源文档检查结果保持不变。8/16 位可见 RGB 的捕获/回传最大误差为 0，32 位为约 `5.96e-8`；Alpha 误差为 0。真实 sRGB ICC 的 652 字节保持一致，300 DPI 等价，浮点 HDR 样本仍存在。回传误差以原生输出为参照，不是把磨皮结果与磨皮前图像比较。

但 PhotoCraft 平面 TIFF 导出会清零完全透明像素下的隐藏 RGB，因此**不能称为严格无损交换**。另存临时 `.pcraft` 则能取得原始 256 × 256 浮点图块；对已知 64 × 48 RGBA32 样本，含隐藏 RGB 的全部像素最大差异为 0，ICC 引用和 DPI 也存在。当前证据来自只读 Python ZIP/zstd 探针，**Rust `.pcraft` 读写器和原生回传此格式尚未实现**；这是下一阶段应优先完成的数据通道。

## 产品边界与尚未解决的问题

- **回传竞争窗口。** 当前按文档索引操作；“检查版本”与“写入”不是一个原子命令，保存也依赖活动文档。版本守卫能拒绝普通过期结果，但不能保证用户同时切换/关闭/编辑文档时绝不误投。首版应默认输出文件或打开新结果文档，手动确认转移；自动替换原层暂不作为承诺。
- **启动与连接。** 需用控制参数、私有 token 和专用读写目录启动 PhotoCraft。无法直接接管未启用控制接口的普通已开实例。启动器及连接恢复还没产品化。
- **初始图层范围。** 首版限定 sRGB、无选区、普通顶层像素图层、Normal、100% 不透明度/填充、无蒙版/剪贴/图层效果。组、智能对象、复杂混合与多通道编辑尚未认证。二进制数据支持 32 位浮点，不等于完成 HDR 磨皮或显示适配。
- **色彩。** 保留 ICC 字节不等于完成显示色彩管理；当前肤色模型仍按已有 RGB 假设工作，广色域需明确转换与显示路线。
- **进度与取消。** 已有阶段/已用时间事件；完整滤镜在大区域内部尚不能细粒度中断，首次缓存准备也类似。GUI、任务排队、丢弃过期帧、完成标识和 ETA 尚未完成，不能展示伪造的剩余秒数。
- **交付形态。** `dist/natural-skin-companion` 是 macOS arm64 CLI 原型，不是可双击的 `.app`、安装包或已签名发行版；没有 GPU 加速实测。

## 开发决定

采用“**原生核心 + 自有异步预览界面 + PhotoCraft 文件/控制适配层**”。PhotoCraft 负责文档编辑；伴随程序负责缓存、处理、预览和任务状态。先完成原始快照适配及安全的新文档回传，再接 GUI 和色彩管理，最后做真实人像端到端验收、内存优化和发行包装，详见 [开发顺序](native-roadmap.zh-CN.md)。

WASM 的构建、清单、ABI 和自动发行入口已退役；保留的 [旧文档](history/wasm/README.zh-CN.md) 仅用于追溯算法与历史测量。
