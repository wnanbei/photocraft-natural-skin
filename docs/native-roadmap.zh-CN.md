# Natural Skin 原生开发顺序

当前已完成 Rust 原生交换、后台任务和跨平台 GUI 的首个开发版，详见 [本轮实现](native-development-2026-11-08.zh-CN.md)。下面列出整体顺序；其中原始交换和基础界面已落地，产品级宿主协调、色彩管理及发行验收仍待完成。以下工作都遵守“不修改 PhotoCraft”，默认以新文档接收结果。

| 顺序 | 工作 | 完成标准 |
| --- | --- | --- |
| 1 | Rust 原始 `.pcraft` 交换适配 | 从临时图层快照读取像素、原点、Alpha、位深、ICC/DPI；支持格式版本检查、图块完整性校验、解压/内存限额；生成可由原版 PhotoCraft 打开的结果快照 |
| 2 | 产品级交换协调器 | 封装独立交换目录与 token 生命周期、捕获失败清理、超时状态、源版本守卫；默认打开新结果文档；原文档切换/关闭/编辑时不自动替换图层，不重试结果不明的变更命令 |
| 3 | 异步原生界面 | 后台 worker、最多一个当前任务、取消/丢弃旧结果、不可变源图会话；小图快速预览和确认后全分辨率处理；界面可显示前后对比、皮肤范围与处理中/完成/失败状态 |
| 4 | 显示与皮肤效果验收 | 先明确 sRGB 路线，接 ICC 显示转换；测试缩放时半径映射、预览与最终图一致性、皮肤边界与纹理。完成前不宣称广色域/HDR 编辑可用 |
| 5 | 细进度、取消和资源预算 | 给长滤波阶段加入分段检查点，统计阶段耗时；显示已用时间，样本足够后才估算剩余时间；优化 24 MP 以上峰值内存，验证取消不发布半成品 |
| 6 | 真实工作流和打包 | 多张经授权人像、不同肤色/光线、透明图层、ICC、16/32 位、断开连接/关闭文档/磁盘写失败测试；测捕获到可见结果的端到端时间；macOS `.app` 包装与签名，之后再验证其他系统 |

GUI 可先用手动打开 TIFF 验证交互，同时推进原始图块通道。预览应复用现有 Rust 缓存；首版以 CPU 为基线，是否投入 GPU 由完整链路测量决定。GUI 已按用户选择采用 Rust + egui 共用 Windows/macOS 实现；没有承诺发行日期。

当前桌面 API 缺少原子“源版本检查并应用”，不能用多做一次检查消除所有竞争。即使新协调器完成，也应把自动原位替换视为单独的后续能力，按其实际安全边界设计。
