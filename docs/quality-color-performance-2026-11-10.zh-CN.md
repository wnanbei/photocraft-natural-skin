# 原分辨率预览、ICC 与大图处理：2026-11-10

本轮沿用 Rust + egui 桌面路线，处理真实效果验收所需的预览工具、SDR 色彩转换和大图资源问题。用户确认暂时没有授权人像，因此本轮使用合成样本；没有把程序性检查当作真人观感或显示器认证。

## 1:1 局部预览与效果检查

- **Fit** 保留缩小图上的快速近似预览。点击图像，或选择 **1:1 detail**，进入原分辨率局部预览。
- 1:1 按物理像素显示，一个源像素对应一个显示像素；使用最近邻采样。拖动或方向键平移；Shift + 方向键移动更大距离。**Fit** 返回全图。
- 局部范围随可用画布调整，每边最多 1024 像素；从完整不可变源图提取两倍滤波半径的上下文。边缘和内部接缝与整图内核对照，允许浮点误差小于 2×10⁻⁶。
- Original、Retouched 和 Skin mask 使用同一局部范围。导出使用完整源图，与当前查看范围无关。
- 进度条固定保留空间；裁剪只随窗口尺寸、查看模式或中心位置变化重算。进度/错误提示不会反复取消预览，也不会因自动预览清除 ICC 设置错误。

`quality-suite OUTPUT_DIRECTORY` 生成六种明暗肤色的确定性噪声色块、深色细线、蓝色背景、透明区域，以及 smooth / texture / tone / mask TIFF 和 JSON。检查降噪、纹理控制、受保护区域和 Alpha；噪声 MAE 是合成诊断指标，不是磨皮质量评分。真人的毛孔、发丝、痘印、肤色过渡、不同光照仍需授权照片及人工对比。

## SDR RGB ICC 路径

使用锁定版本的 moxcms 0.8.1，先将源 RGB ICC 转换到编码 sRGB 工作空间，执行磨皮/调色，再转换回源色彩空间。保留原 ICC、位深、Alpha、DPI 和 pcraft 元数据。未标记图像明确按 sRGB 解释。

- 支持 SDR RGB matrix/TRC 配置，使用相对色度意图；ICC 解析限额 4 MiB，并限制曲线和 LUT 预算。
- 无法解析、非 RGB、LUT、带 PQ/HLG CICP 的配置明确报错，提示先在 PhotoCraft 转为 sRGB，不静默丢弃配置。
- 无改动像素直接保留源编码，避免纯往返转换积累误差；透明像素下 RGB、非有限值和原始 HDR 样本保持不变。转换到 sRGB 后落在工作域之外的像素不参与磨皮。改动后转回源编码的 SDR RGB 限制在 0–1。
- 默认向画布提供 sRGB 像素。**Display profile…** 可为图像画布显式选择显示输出 ICC，**Use sRGB output** 恢复默认；设置只影响预览，不影响导出，本轮不持久保存此选择。如果 OS 已经把窗口的 sRGB 输出转换到显示器，应使用默认输出，避免重复转换。
- 原图和效果使用同一显示变换。显示配置变化、跨显示器移动及真实显示器校准尚未自动处理或实测；不宣称完成 Windows/macOS 的全链路显示色彩管理，更不宣称 HDR 编辑/显示认证。

测试覆盖 P3→sRGB 独立矩阵/传递函数参考值、P3 显示输出的扩展色域往返、Adobe RGB 无操作逐位保留、Alpha/隐藏 RGB/HDR 保留，以及无效/灰度/PQ 配置拒绝。

实现参考：[moxcms API](https://docs.rs/moxcms/0.8.1/moxcms/struct.ColorProfile.html)、[ICC RGB 工作流说明](https://www.color.org/ICC_white_paper_23_RGB_Workflow.pdf)、[ICC 对显示转换的说明](https://www.color.org/faqs/)。

## 大图资源、取消与测量

GUI 和 CLI 导出共用 `processing::process`：从不可变源图逐块处理 256×256 的输出区域，仅保留当前块及两倍半径上下文。完整输出另占一个 RGB/RGBA 浮点缓冲；文件解码、原图、预览缓存、ICC 执行器及编码缓冲仍占内存，工作区上限不等于进程峰值。

- 半径最大 20 时，每块上下文不超过 336×336，七个滤波平面最多 **3,161,088 字节（约 3.01 MiB）**，不随 24/36 MP 图像总面积增长。
- 保留块级完成比例；滤波行、列组、缓存准备、调色和蒙版路径加入取消检查。完整输出分段初始化也检查取消。
- 后台进度通知合并到约每 33 ms，阶段切换和阶段完成立即发送，避免每个检查点都堆积 UI 消息。
- 取消时丢弃私有结果，不更改源图，不发布半成品。解码、ICC 初始化、OS 打开和最终文件提交仍有不可中断区间；没有 ETA。
- CLI `process` 输出读取、处理、写入、总耗时、块数及缓冲字节；GUI 导出完成显示滤波/写入耗时和块缓冲估算。

复现（先构建，测量期间不要同时编译或跑其他基准）：

```sh
sh build.sh
python3 native/tests/benchmark_acceptance.py --output test-output/acceptance-2026-11-10
```

脚本依次运行整图内核/分块的 24 MP 基准、缓存预览、三次异步取消、24 MP TIFF 读→ICC→处理→写入、无改动往返与原图哈希检查。分别记录内核时间、整进程最大 RSS 及文件流程时间；PhotoCraft 捕获/回传和 GPU 显示上传不在此文件流程计时内。原始记录及本轮验收结果见同名 JSON。

## 本机合成测量结果

macOS arm64，release 构建，6000×4000 RGBA；两条处理路径各测三次。整图路径和分块路径使用同一内核，后者还包括完整输出缓冲的分配/复制。结果用于评估本轮内存取舍，不是与已发布 WASM 或真实照片比较。

| 测量项 | 整图基线 | 分块路径 |
| --- | ---: | ---: |
| 处理时间中位数 | 1.465 s | 1.541 s |
| 子进程峰值 RSS | 1009.2 MiB | 744.1 MiB |
| 滤波工作区 | 640.87 MiB | 2.09 MiB |

本样本峰值 RSS 降低 **26.3%**，处理时间增加 **5.1%**。不承诺所有输入同样变化。1024×768 缓存预览混合中位数 **16.70 ms**。

带 sRGB ICC 的 24 MP RGBA16 TIFF 文件流程：读取 **59.6 ms**，处理 **4.069 s**，写入 **186.6 ms**，合计 **4.315 s**，RSS **928.3 MiB**。其中 ICC 转换和文件编码的内存/时间不能从纯内核数字推算。Alpha、隐藏 RGB、ICC、DPI 保留；Strength=0 往返逐样本差异为 0，原输入哈希未变。

三次 24 MP 异步取消测得响应延迟 **0.012–0.035 ms**，范围仅为开始滤波后 20 ms 发出请求到分块处理返回，不包含解码、GUI 调度、ICC 初始化或文件提交。这是本机三个样本，不是最坏延迟上限。

六组肤色噪声色块在 Strength=100、Texture=0 时，内部 RGB 绝对误差约为输入的 **15.0%**；Texture=100 时约为 **41.1%**，符合增加纹理保留的预期。蓝色背景和透明像素数据最大差异为 0；这不代表真人纹理已通过主观验收。

完整原始测量、构建哈希及限制见 [JSON](quality-color-performance-2026-11-10.json)。
